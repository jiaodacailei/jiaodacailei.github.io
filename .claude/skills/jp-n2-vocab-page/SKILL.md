# N2词汇参考页生成/增量更新

跟姊妹skill `jp-n2-grammar-page` 共用同一个构建脚本
`tools/listening/build_n2_reference_page.py` 和同一套页面基建（TTS合成+Whisper
对齐+`mcq-quiz.js`四选一引擎）——**先读一遍 `jp-n2-grammar-page/SKILL.md`**，
密码/枢纽页约定、后台跑构建脚本的注意事项、参考答案在附录页这几条完全一样，
不重复写。这份文档只写**词汇内容形状特有**的坑，跟语法点不一样的地方。

## 内容模块——每个单词是一个"point"

复用跟语法点完全相同的 `UNITS`/`MCQ_UNITS` 数据形状（脚本docstring原话："语法点
或者单词条目，都是标题+讲解+若干例句"）——每个单词映射成一个 `points` 条目：
`title` = "<编号>. <单词>（<读音>）"，`overview` = 词性/释义（中文），`examples`
= 书上给的例句(日语,中文)二元组列表。

## 覆盖范围：跟语法点"少而准"的策略正好相反——每个词条都要收录

语法点转录时，例句可以"读不准就跳过那一条"；**词汇页不一样：每一行词条本身
就是独立的学习内容**（不是某个知识点的补充说明），跳过一个词条等于让学习者
少学一个单词，所以：

- **单词/读音/词性/释义这几个字段本身不能跳**——反复裁剪/放大重读，也不要
  为了省事只收录"练习题抽样考到的那些词"（这是本skill第一次做词汇01时
  踩过的一个认知偏差：练习题问题1只抽查了75个词的读音默写，一开始误以为
  "这本单元只有75个词"，实际把255-265页词条正文全部数一遍才发现有153个——
  练习题的抽样量不代表词表本身的大小，转录前要先把词条正文页全部翻一遍
  确认真实词条数，不能用练习题反推）。
- **允许跳的只有"某个词条的例句"**（书上确实没配例句，或者例句被拍照边缘
  裁掉、怎么放大都读不出来）——这种情况下这个词条的 `examples` 留空列表
  `[]`，词条本身（标题+读音+释义）照常收录，在模块docstring里说明"哪个
  词条没有例句、为什么"。**这类"有词条无例句"的情况必须确认
  `tools/listening/build_page.py` 的 `_group_by_mondai_question()` 是修复后的
  版本**（分组骨架以 `questions` 列表自身顺序为准，不是靠扫一遍 `sentences`
  才发现分组）——旧版本会导致这类词条从页面上完全消失，是本skill第一次
  实践时发现并修复的真实bug，细节见下面"已跑过的真实案例"。
- 书上偶尔会给"类/对/同"提示（同义词/反义词/同音词参照），如果这个参照词
  **没有自己独立的四位流水号**，就并进被参照的主词条 `overview` 里，不单开
  卡片；如果**有自己的流水号**（哪怕例句是"参见XX"这种没有独立例句的情况），
  仍然要给它开一张独立卡片（走上一条"允许跳例句、不允许跳词条"的规则）。

## 词条编号：优先保真内容字段，编号本身可以是转录者自己重排的

源照片是竖排日文分栏排版，书本身的四位流水号（0001、0002……）在栏与栏、
页与页之间的顺序有时需要反复放大比对才能确认对齐；这个编号不影响任何页面
功能（四选一题目靠题干文本本身跟词条内容匹配，不靠编号做外键关联）——遇到
编号本身分辨率不够、无法101%确认时，用转录者自己按阅读顺序重新连续编号，
在模块docstring里说明"标题里的编号是重新编的，不是书本原始流水号的逐字
还原，不要拿它跟书对页码"，优先保证"单词/读音/释义/例句"这些真正影响学习
内容的字段准确，不要在编号这种纯展示用的元数据上卡住转录进度。

## 练习题：問題1"读音默写"这种题型天生跟四选一引擎不合，直接跳过

单词书的练习题常见有两种：問題1"给汉字词写假名"（默写题，没有选项，书里
也不给参考答案候选——本来就是要学生自己写），問題2"四选一"（跟`MCQ_UNITS`
形状完全匹配）。問題1不用勉强塞进四选一引擎（更不要把"正确读音"包装成
4个选项自己发明3个错误选项），跳过它、只转录問題2，在docstring里写清楚
"問題1题型不合，不是没转录能力"。

問題2转录时如果个别题目因为**手写体/排版导致干扰项（错误选项）文字看不
真切**，可以按"语义合理的同类词"重建干扰项文字，只要**正确选项**跟答案页
逐一核实过、且对应的词条已经在 `UNITS` 里收录——这不影响判分（选对该选的
那个就算对），只影响"选错时具体看到的干扰项日文措辞"跟原书是否逐字一致，
在docstring里注明这个精度取舍。如果连题干本身（哪个词条被考、大致语境）都
看不清楚，才应该整题跳过，并在docstring里写清楚跳过了哪几题、为什么——
跳过的题对应的词条本身仍然完整保留在 `UNITS` 里，不受影响。

## 标题本身也能默写/填空——转录时全角括号是硬性要求，不只是排版习惯

`question-block` 的标题（"0001. 相変わらず（あいかわらず）"这种）在默写/填空
模式下会被隐藏，换成一个默写输入框（连同侧栏目录的日语也会换成中文），
`listening-page.js` 判断"要默写的答案是什么"完全靠一条正则：去掉开头的
编号前缀，再去掉结尾**全角**括号"（……）"包住的内容——这就是为什么词条
读音/词源提示必须用全角括号写（"（あいかわらず）"「（idea）」），不能写成
半角"(...)"：写成半角会导致这段正则匹配不上，默写答案就会把读音也一起
包进去，变成要求"单词+读音"连着打对，实际达不到"日语本身即可"这个已经
定好的判分标准。反过来，如果词条本身的日文原文里恰好需要出现半角括号
（目前词汇页还没遇到这种情况，但要留意），会被这条正则当成"不用默写的
读音提示"整段吃掉——真遇到这种词条，转录时要么改用全角，要么在
`listening-page.js` 里想办法排除，不能假装没看见。

侧栏目录换成中文时显示的文字，直接复用 `overview` 第一行（过滤掉"接续："/
"接続："开头的行，防止语法点原文被提前泄露——这条过滤对词汇条目通常是
空操作，因为词汇的 overview 从不这样开头），不需要给内容模块另外加字段。

## 单元选择下拉框——加第2个单元时自动出现，不用额外做任何事

跟姊妹skill共用的同一套机制：`UNITS`/`MCQ_UNITS` 里出现2个及以上不同的
`label`（"第1单元"/"第2单元"……）时，页面顶部会自动出现一个"单元选择"
下拉框（"N2词汇 | [单元选择▾] | 生词 | 練習"），选哪个单元，"生词"tab的
词条列表和"練習"tab的题目一起跟着换。以后加词汇02，只需要往
`n2_vocab_content.py` 末尾追加一个 `label: "第2单元"` 的新单元、重新跑
一遍构建命令，不用碰任何前端代码——这一点参见 `jp-n2-grammar-page/
SKILL.md` 里更详细的说明（两个skill这部分完全共用同一套实现）。

## 构建命令

```bash
python tools/listening/build_n2_reference_page.py docs/private/n2-vocab \
  tools/listening/n2_vocab_content.py \
  --title "N2词汇" --subtitle "词汇01" --tab-label "生词" \
  --password-hash <摘的哈希>
```

## 已跑过的真实案例／踩过的坑

- **`_group_by_mondai_question()` 分组丢词条的bug**：词汇01第1单元153个
  词条里有21个没有配例句（书上就是只给了词头+释义）。`build_page.py` 共用
  的分组函数原来靠"扫一遍 `sentences`"来决定页面上有哪些分组、顺序是什么——
  这21个零例句的词条在 `sentences` 里完全不出现，导致整个词条（标题+读音+
  释义）从页面上完全消失，不是"缺一条例句"这么轻。第一版补丁只是在
  sentences循环之后把这些遗漏词条"追加"到每个mondai分组的末尾——结果内容
  没丢了，但顺序全乱了（比如"0005"被甩到"0153"后面）。**正确的修法是把
  分组骨架的构建顺序完全交给 `questions` 列表自己的顺序**（这才是作者/
  教材原本的真实顺序），`sentences`只负责往已经建好的骨架里填内容，不负责
  决定骨架长什么样、按什么顺序排。这个函数是 `jp-textbook-lesson`（课文页）
  和"单词测试"quiz功能共用的核心分组逻辑——改的时候要确认现有页面的
  `questions`/`sentences`构建顺序本来就是一致的（几乎所有现有调用点都是
  在同一次遍历里同时构建两者），不会因为改成"以questions顺序为准"而让
  旧页面的分组顺序发生变化。
- **两次因为后台进程管理不当导致的构建竞态**：细节记在
  `jp-n2-grammar-page/SKILL.md`（两个skill共用同一个构建脚本，踩的是
  同一类坑）——词汇页因为句子数量大（206句 vs 语法页14句），构建耗时长
  （几分钟到二十几分钟不等），更容易在"看着卡住"时手痒重新发起一次，
  一定要靠"收到完成通知"而不是"觉得应该跑完了"来判断是否可以进行下一步。
